# Test Analytics Backend — V2 (BGW720)

Live-data backend for:
SQL Server -> Node.js/TypeScript -> React dashboard -> AI chat.

## Requirements
- Node.js 20+ (LTS recommended)
- npm 10+
- Access to your SQL Server
- SQL Server credentials or Windows/Entra authentication configured for your environment

## Setup

1. Copy `.env.example` to `.env`.
2. Fill in your SQL Server settings.
3. Install dependencies:

```bash
npm install
```

4. Start development server:

```bash
npm run dev
```

The API runs on `http://localhost:3000`.

## Endpoints

- `GET /health`
- `GET /api/dashboard/summary?startDate=2026-08-20&endDate=2026-08-20`
- `GET /api/dashboard/failures-by-station?startDate=2026-08-20&endDate=2026-08-20`
- `GET /api/dashboard/failure-reasons?startDate=2026-08-20&endDate=2026-08-20`
- `GET /api/dashboard/trend?startDate=2026-08-20&endDate=2026-08-20`
- `POST /api/chat`

## Live data mapping

| Endpoint | Approved database source |
| --- | --- |
| `/summary` | `dbo.sp_BGW720GetTestSummary` |
| `/failures-by-station` | `dbo.sp_BGW720GetFailuresByStation` |
| `/failure-reasons` | Parameterized read from `dbo.vw_BGW720ReflashTestResults` |
| `/trend` | `dbo.sp_BGW720GetTestSummary` (daily rows) |

All four endpoints read SQL Server when requested; there is no scheduled dataset refresh or API cache in this version.

Install/update the database objects using the numbered scripts under `database/`. See `database/README.md` for execution order and permissions.

## Chat

The V2 keeps a safe placeholder `/api/chat` endpoint. It does NOT execute arbitrary SQL generated by an LLM.

The intended next step is to connect an LLM provider to `src/services/aiService.ts` and expose only approved backend tools such as:
- getTestSummary
- getFailuresByStation
- getFailureReasons
- getTestTrend

Each tool must call one of the approved service functions; the model must never receive database credentials or execute SQL text.

## Example response fields

`/summary` and `/trend` return daily rows containing `TestDate`, `Total`, `FT_Pass`, `FT_Fail`, `FT_Yield`, `LT_Pass`, `LT_Fail`, and `LT_Yield`.

`/failures-by-station` returns `Station` and `Failures`. `/failure-reasons` returns `FailureReason` and `Failures`.
